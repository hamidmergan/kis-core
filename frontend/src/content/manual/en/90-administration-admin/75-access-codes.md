# Access codes and invites

Two ways to give people an account without a central login. Both need the server switch for
account creation, if it is off, this page only shows a notice that both are switched off.

## Invites

A single link for one person. The title is the username, usually Firstname.Lastname or a
shorthand, the email address is optional. Plus role and validity in days. The link redeems exactly
once, afterwards it shows as redeemed, a still-open invite can be withdrawn.

## Access codes

A code for a whole test round or event, several people redeem the same code.

- **Title, how often redeemable, code valid** (days), **access valid** (hours or unlimited),
  **role**.
- **Show credentials**: off means the person is logged in directly on redeeming, without seeing a
  username and password, meant for events with a QR code on a projector.
- **Show evaluation**: on means accounts from this code are offered the evaluation on the start
  page.
- **Workspaces**: whoever redeems the code is enrolled in the chosen workspaces right away.
- Each code shows its own QR image to download. Switching on or off, editing (everything but the
  code itself), and deleting are possible at any time, switching off is usually enough, then no
  new accounts join while the existing ones stay visible.
- Per code the accounts it created, with status, valid until, deletion on, a new password can be
  set, plus the person's activity: workspaces visited, the last 50 chat entries.
- **Delete expired test accounts**: how many days after expiry a locked test account is deleted
  for good, together with its workspaces, chats, and files. Answers from the evaluation stay on
  anonymously. 30 days by default, 0 means never.
