# Summary

Brings several sources together into one text, as a short briefing, study guide or timeline.

![The summary service](/manual/{lang}/tool-summary.png)

## Sources

Up to ten files per job, as PDF, Word, PowerPoint, text, Markdown, or subtitles. How many
characters and pages a single file may carry is set by the management in the admin area
under Limits. Out of the box it is 500,000 characters and 200 pages per file, and ten
times the character count for all files together. Only the text layer is read. Scanned pages without text are left out, and a PDF with no text at all
is rejected with a message.

Each file goes into one call whole. If the chosen model cannot hold a file, the service
refuses the job with a message naming the file and the model. A larger model in the
provider picker solves that.

## Template

Short briefing, study guide, or timeline. The template decides what is read out of the
sources first and how the text is organized. The number of sections depends on how much the
sources contain.

## Duration

Every source is read once, then the text is written section by section. A law of a good 200
pages takes a few minutes, you can leave the page in the meantime, the job keeps running.

## The result

The text comes as Markdown and as a Word file with a cover page and a table of contents.
Where your material names the part a statement rests on, such as a section or an article,
that reference stands behind the statement.

## What to expect

A summary is a shortening and inevitably leaves something out. It does not replace the
original when accuracy matters.

## The difference to the chat inside a workspace

The service delivers a text to download. The chat inside a workspace works across all
ticked materials and backs every statement with the spot it came from.
